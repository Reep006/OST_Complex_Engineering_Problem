# Contributing Guidelines

Thank you for contributing to the OST Complex Engineering Problem repository.

## 1. Create a Branch

Do not directly make development changes in the `main` branch.

Create a separate feature branch.

Example:

`feature/documentation-improvement`

## 2. Make Changes

Make the required changes in the feature branch.

Check the files before committing.

## 3. Commit Changes

Use clear and meaningful commit messages.

Examples:

- Add README documentation
- Add issue templates
- Update project file
- Fix documentation issue
- Resolve merge conflict

## 4. Push the Branch

Push the feature branch to GitHub.

`git push origin feature/documentation-improvement`

## 5. Create a Pull Request

Create a pull request from the feature branch to the `main` branch.

Explain:

- What was changed
- Why the change was required
- Any important information about the change

## 6. Review

The changes should be reviewed before merging into `main`.

## 7. Merge

After successful review and conflict resolution, the feature branch can be merged into `main`.

## Branch Naming Convention

Use descriptive branch names.

Examples:

- `feature/documentation`
- `feature/issue-template`
- `feature/project-update`
- `fix/readme-error`

## Commit Naming Convention

Use short and meaningful commit messages.

Examples:

- Add documentation
- Update README
- Add issue templates
- Fix project file
- Resolve merge conflict

## General Rules

- Keep changes focused.
- Do not commit unnecessary files.
- Keep documentation updated.
- Follow the repository structure.
- Check the repository before creating a pull request.
